# Manifest reconciliation and observable staleness

Version 0.5 implements exact, bounded snapshot comparison. It does not implement distributed gossip, rateless encoding, replica quorums or probabilistic bounded staleness (PBS). Research performance statistics in the supplied notes are not measured platform results.

Controllers configure `/integration/policy` with max_pending_seconds (default 300), max_source_age_seconds (3600), and reconciliation_interval_seconds (30). Values are validated and organization scoped. The worker polls every five seconds and processes a due organization according to its policy. These are operational detection thresholds; partitions, missing source data, processing failures and workload can exceed them. They are not hard visibility or replication guarantees.

GET `/integration/manifest?entity_id=...&connection_id=manual` exports the latest local source versions, including persistent tombstones. Each record contains external_id, version, payload_hash and tombstone. The sorted set has a deterministic manifest_hash. The exact comparison is limited to 10,000 identities; larger sources must be partitioned before using this interface. Hashes must be calculated using the platform's canonical normalized source payload, including decimal normalization. A hash of an arbitrary ERP export is not comparable.

POST `/integration/reconcile` accepts entity_id, connection_id, observed_at, watermark and records. The caller must supply an authoritative complete snapshot for that identity scope, including retained deletion markers. observed_at is timezone aware, cannot be in the future, and must advance the previous observation. The opaque watermark is retained as provenance, not interpreted as a numeric ordering key. The authenticated controller attests to the manifest; this does not independently certify source completeness.

The response identifies missing_local, unexpected_local, divergent and corrupt_local identities. Comparison detects version, content hash and tombstone differences. No monetary facts are merged, missing sources invented, or unexpected sources deleted. Fetch missing revisions from the authorized source and submit ordinary ordered events; resolve conflicting authority under controller review. Existing idempotency and tombstone controls apply during repair.

GET `/integration/status` includes freshness: oldest pending receipt age, threshold breach, and latest observations with their age, watermark and convergence. It recomputes each observation against current source state instead of trusting a historical comparison result. No source observation yields upstream_status=unverified, even if the received queue is empty. Only observed source scopes are listed; this does not establish coverage of all enterprise sources. Source event timestamps cannot establish completeness. The worker persists actionable check summaries as analysis runs and audit alerts. Healthy idle checks do not append records. Alerts remain local; there are no email notifications.

Start-Finance.ps1 now launches API, dashboard and a single worker, all recorded for Stop-Finance.ps1. The worker runs local inbox projections and comparisons against retained observations; refreshing remote manifests remains the responsibility of a live source adapter or operator. Docker deployments must run `python -m app.worker` in a dedicated worker process. Multi-worker leases, authenticated remote snapshot collection, partitioned manifests, efficient set-difference transport, alert deduplication/retention and fault/load benchmarks remain production work.

Release 0.5.1 adds the dedicated worker service to docker-compose.yml, dependent on the migrated healthy API. Docker execution remains unverified locally.
